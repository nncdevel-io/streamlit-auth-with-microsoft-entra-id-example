## 1. 概要

本ドキュメントは、StreamlitアプリケーションにMicrosoft Entra ID（旧Azure AD）を使用したOIDC認証を組み込むサンプル実装の要件を定義する。

### 1.1 目的

- StreamlitアプリケーションにEntra IDによるシングルサインオン（SSO）を実装する
- 認証後のユーザー情報（ID、名前、メール）を取得し、アプリケーションで利用可能にする

### 1.2 スコープ

**対象範囲:**

- Entra IDを使用したOIDC認証フロー（Authorization Code Flow）
- IDトークンの検証とクレーム取得
- ユーザー情報の`st.session_state`への格納
- ログイン・ログアウト機能
- Cookie + HMAC署名によるCSRF対策

**対象外:**

- ユーザー管理UI
- マルチテナント対応

## 2. 機能要件

### 2.1 認証機能

#### REQ-1: ログイン機能

未認証ユーザーがアプリケーションにアクセスした際、Entra IDのログイン画面にリダイレクトする。

#### REQ-2: コールバック処理

Entra IDからの認可コードを受け取り、トークンエンドポイントでIDトークン・アクセストークンに交換する。

#### REQ-3: IDトークン検証

受け取ったIDトークンの署名、発行者（issuer）、対象者（audience）、有効期限を検証する。

#### REQ-4: ログアウト機能

セッションをクリアし、Entra IDのログアウトエンドポイントにリダイレクトする。

#### REQ-5: CSRF対策

OAuth認証フローにおいて、Cookie + HMAC Double Submit方式でstateパラメーターを検証する。

### 2.2 ユーザー情報管理

#### REQ-6: ユーザー情報の取得

IDトークンのクレームから以下の情報を取得する。

| クレーム | 説明 |
|---------|------|
| `sub` | ユーザー識別子（Subject） |
| `name` | 表示名 |
| `preferred_username` | ユーザー名（通常はメールアドレス） |
| `email` | メールアドレス |

#### REQ-7: セッションへの格納

認証情報を`st.session_state`に格納し、アプリケーション全体で利用可能にする。

#### REQ-8: 認証状態の確認

任意のページで認証状態を確認できるユーティリティ関数を提供する。

## 3. 非機能要件

| 項目 | 要件 |
|------|------|
| Python バージョン | 3.13以上 |
| Streamlit バージョン | 1.37.0以上（`st.navigation()`, `st.context.cookies`） |
| 依存関係 | `streamlit`, `msal`, `python-dotenv`（pyproject.tomlで管理） |
| セキュリティ | クライアントシークレットは環境変数で管理、コードにハードコードしない |
| CSRF対策 | Cookie + HMAC Double Submit方式（セッション依存なし） |
| エラーハンドリング | 認証エラー時は適切なエラーメッセージを表示 |

## 4. Entra ID設定要件

### 4.1 アプリ登録

Azure Portalで以下の設定を行う。

| 項目 | 設定値 |
|------|--------|
| アプリケーションの種類 | Web |
| リダイレクトURI | `http://localhost:8501/callback`（開発時） |
| サポートされるアカウントの種類 | シングルテナント or マルチテナント |
| IDトークン | 有効化 |

### 4.2 APIのアクセス許可

| アクセス許可 | 種類 | 説明 |
|-------------|------|------|
| `openid` | 委任 | OIDC認証に必須 |
| `profile` | 委任 | ユーザープロファイル取得 |
| `email` | 委任 | メールアドレス取得 |
